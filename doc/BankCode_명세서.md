## 2. 기능 설명

### 2.1 버튼
- 조회: 조건 텍스트(은행코드/명)와 유사한 항목 조회 (빈칸: 전체)
- 추가: 새 행 추가(기본값: 적용일자=2000-01-01, 송금수수료=0, 사용여부=Y, 정렬순서=마지막+1)
- 삭제: 선택 체크박스가 체크된 행 삭제(확인 팝업)
- 저장: 변경/추가된 행만 전송하여 서버에서 기존 JSON과 병합 저장(부분 저장)

### 2.2 조건 영역
- 입력 필드: 은행코드/명 (부분 일치 검색)
- 조회 버튼 클릭 시 검색 수행

### 2.3 그리드
- 선택: 체크박스(일괄 삭제)
- 은행코드: 숫자만, 최대 3자리, 필수
  - 입력 UX: 3자리 미만 입력 시 포커스 유지, 3자리 도달 즉시 같은 행의 은행명으로 포커스 이동
  - 컬럼 너비: 약 8rem (절반으로 축소)
- 은행명: 텍스트, 필수 (컬럼 너비: 약 16rem)
- 적용일자: 달력 입력(yyyy-MM-dd), 기본 2000-01-01
- 송금수수료: 숫자, 기본 0
- 정렬순서: 숫자, 0~999 권장
- 사용여부: 드롭다운(Y=사용, N=미사용)
- 비고: 자유 입력, 남는 폭 전체 사용(가변 폭)

검증/제약
- 저장 전 은행코드/은행명 필수 확인
- 적용일자 형식(yyyy-MM-dd) 검증
- 은행코드: 숫자만 허용, 최대 3자리

## 3. 데이터 구조도

클라이언트-서버 간 전송(JSON)
```
BankCode {
  bankCode: string,
  bankName: string,
  effectiveDate?: string, // yyyy-MM-dd
  remitFee?: number,
  sortOrder?: number,
  useYn?: 'Y'|'N',
  remark?: string,
  regDate?: string,
  modDate?: string,
  regUser?: string,
  modUser?: string,
}
```

백엔드 저장(JSON 파일)
- 파일: `backend/data/bank_codes.json`
- 구조: 배열(Array)

## 4. UML 다이어그램

### 4.1 클래스 다이어그램(논리)

```
+-------------------+           +-----------------------+           +-------------------+
|   BankCodePage    |           |   BankCodeController  |           |  BankCodeService  |
|-------------------|           |-----------------------|           |-------------------|
| - banks: List     |  fetch()  | + getAll(): List      |  getAll() | - DATA_FILE       |
| - originalBanks   |---------> | + search(q): List     |---------> | + getAll(): List  |
| - selected: Set   |           | + save(List): 200     |  save()   | + searchByKeyword |
| - keyword: string |  save()   | + delete(List): 200   |<--------- | + save(List)      |
|-------------------|---------> |                       |  delete() | + deleteByCodes   |
| + handleSave()    |           |  (REST @ /bank-codes) |<--------- | + getAllSorted    |
| + handleDelete()  |           +-----------------------+           | - writeAll(List)  |
| + fetchBanks()    |                                             | + initializeDefault |
| + updateCell()    |                                             +-------------------+
```

- BankCodePage: 변경 추적(`originalBanks`) 후 변경/추가 항목만 저장
- BankCodeController: REST 엔드포인트 집합(`/api/bank-codes`, `/search`)
- BankCodeService: JSON 파일(`data/bank_codes.json`) 기반 병합 저장 로직

## 5. 프런트엔드 동작 흐름
- 조회: 입력 텍스트 -> `/api/bank-codes/search?q=` 호출 -> 목록 표시(정렬순서 오름차순)
- 추가: 새 행을 최상단에 추가
- 삭제: 선택 -> `/api/bank-codes` (DELETE) -> 재조회
- 저장: 변경/추가된 행만 -> `/api/bank-codes` (POST) -> 서버 병합 저장 -> 재조회

## 6. UI 정책 & 제약
- 입력 제약: 은행코드, 은행명 필수 / 적용일자 형식 준수 / 수수료, 정렬순서 숫자만
- 버튼 활성화: 삭제는 선택이 있을 때만 수행 권장
- 에러 처리: 네트워크/응답 오류 시 상단 메시지 노출
 - 포커스 정책: 은행코드 3자리 미만 입력 시 포커스 유지, 3자리 도달 시 은행명으로 이동
